# i18n

## Files

| File | Role |
| --- | --- |
| `i18n.types.ts` | `AppLocale` (source of truth for locales) and dictionary types |
| `i18n.es.ts`, `i18n.en.ts`, `i18n.pt.ts` | One dictionary per locale. Add every new key to all three. |
| `i18n.loader.ts` | `loadLocaleDictionary` and the `I18N_LOCALE_LOADER` / `I18N_PRELOADED_DICTIONARIES` tokens |
| `i18n.service.ts` | Active locale and `translate`; used by the `t` pipe |
| `i18n.translations.ts` | Eager `TRANSLATIONS` aggregate for specs and tooling only |
| `i18n.testing.ts`, `i18n.test-environment.spec.ts` | Test suite preloads every locale |

## Loading

- `es` is in the initial bundle and is the default and fallback.
- `en` and `pt` are separate chunks loaded with a dynamic `import()` the first time they are selected, then cached.
- While a locale loads, the current dictionary keeps rendering (`pendingLocale()` names the locale being loaded); `locale()` is always the rendered locale.
- When selections overlap, the last requested locale wins.
- A failed load keeps the current locale, sets `loadError()` and shows the translated `common.localeLoadError` notice. Selecting the locale again retries.
- At startup (browser language in `AppComponent`, user or organization preferences in `UserPreferencesService`), a non-es locale renders es until its chunk arrives; `<html lang>` follows the rendered locale.

## Rules

- App code must never import `i18n.translations.ts` or a non-es locale file: it would put them back in the initial bundle.
- `i18n.parity.spec.ts` enforces the same key set across locales.
