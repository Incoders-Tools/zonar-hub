### Design decisions (parent, binding for workers)

- **D1 One draw per tournament.** A tournament (already scoped by category and gender) has at most one draw. States: `draft` (editable, regenerable, private) → `published` (visible publicly when the tournament is public). Regenerating or deleting is allowed only while no match has a result. Unpublish returns to private without losing results.
- **D2 Storage (additive migration).** `tournament_draws` (id, tournament_id unique, organization_id, status, format, participation_format, randomization_mode, seed bigint/text, options jsonb, request jsonb = participants and options as submitted, structure jsonb = generated draw snapshot, published_at, created/updated). `tournament_draw_match_results` (draw_id, match_id text e.g. `KO-R1-M3`, status, sets jsonb, winner_side, court_id null, court_name null, scheduled_at, started_at, finished_at, updated_at; unique draw_id+match_id). The structure snapshot is the source of truth for the bracket shape (never regenerated from the seed after save). Follow existing grant conventions (service_role) and tenant scoping by organization.
- **D3 Score model (S6).** Match status: `scheduled`, `in_progress`, `completed`, `walkover`, `retired`. Sets: list of `{ home, away, tiebreak? }`. Best of 3; regular set won 6-0..6-4, 7-5 or 7-6 (with optional tiebreak points); third set may be a super tie-break to 10 (win by 2, e.g. 10-8, 11-9) when the draw options say so (`thirdSetSuperTiebreak`, default true). `completed` requires a valid finished score whose winner matches `winnerSide`; `in_progress` allows a partial valid score; `walkover` requires `winnerSide` and no sets; `retired` requires `winnerSide` and a partial score. Rules live in the domain (pure, tested).
- **D4 Progression (pure domain).** A resolver takes the stored draw structure + results and returns the resolved draw: `WinnerOf`/`LoserOf` slots become participants when the source match has a winner; bye matches auto-advance; group standings per group (won matches, then set difference, then game difference, then head-to-head, then seed order; document) and `GroupPosition` slots resolve when the group's matches are all decided. A result can be entered only when both slots are resolved participants; changing or clearing a result is rejected when its winner already played (has a result) in the next match.
- **D5 Admin API (AdminOrAbove + `TournamentOrganizationAccess` tenant rule).** Under `/api/admin/tournaments/{tournamentId}/draw`: `POST preview` (generate without saving; returns the draw), `PUT` (save/replace draft from a request; 409 when results exist), `GET` (draw + results + resolution), `POST publish`, `POST unpublish`, `DELETE` (draft without results), `PUT matches/{matchId}/result` (status, sets, winnerSide, court, scheduledAt, startedAt, finishedAt; validated by D3/D4). Seed: optional in the request; when absent the API generates one (the only non-deterministic step, outside the domain) and returns it.
- **D6 Public API.** `GET /api/public/tournaments/{slug}/draw` (anonymous, same public filters as the showcase, 404 when no published draw) returns the resolved draw and results with participant display names and members only (no internal ids beyond draw-local participant ids and match ids, no court ids). `Cache-Control: public, max-age=15`.
- **D7 Draw JSON (shared by admin GET/preview and public).** camelCase: `{ status, format, participationFormat, seed, publishedAt, options, participants: [{ id, displayName, members[], seedRank, separationKey? (admin only) }], phases: [{ id, kind, groups?: [{ id, participantIds[], standings: [{ participantId, played, won, lost, setsFor, setsAgainst, gamesFor, gamesAgainst, position }] }], rounds: [{ number, name, restingParticipantIds[], matches: [{ id, roundNumber, number, home: Slot, away: Slot, winnerAdvancesTo, loserAdvancesTo, result: { status, sets[], winnerSide, courtName, scheduledAt, startedAt, finishedAt } | null }] }] }], separationConflicts[] }` where `Slot = { kind: participant|bye|winnerOf|loserOf|groupPosition, participantId?, matchId?, groupId?, rank?, resolvedParticipantId? }`.
- **D8 Frontend bracket view (S2).** One shared, presentational draw view (reuse or replace `shared/components/tournament-bracket/` — do not keep two bracket components): knockout as round columns with header bar and paging (3 columns desktop, 1 mobile; arrows and keyboard accessible), match cards per S2 with connector lines, winner check, BYE, set scores; group stage as group tables (standings) plus matchday lists; pure round robin as matchday list plus standings; list/bracket toggle; match detail panel (status badge, court, round, date, score, duration). Theme tokens only, es/en/pt, accessible (cards are buttons when clickable, ARIA labels with names and score).
- **D9 Admin draw page.** Evolve the existing in-memory `admin-draw-planner-page` (and its `DrawPlannerService`) into the API-backed page reached from the tournaments list ("Grilla" action) instead of adding a second planner: participants entry (table rows and paste of one pair per line `Name A / Name B`, optional seed rank and club), format and options, seed field (optional), preview, save draft, publish/unpublish, delete; then result entry per match (dialog with sets, status, winner, court, schedule) with D3/D4 messages translated.
- **D10 Public page.** The tournament detail page replaces the coming-soon state with the D8 view when a published draw exists (keep the coming-soon/empty state otherwise); polls every 30 s only while the page is visible (Page Visibility API), stops on destroy, and never shows a loading flash on refresh.

- **D11 Lazy translations.** Split `i18n.translations.ts` into one file per locale; `es` (default) stays in the initial chunk, `en` and `pt` load with a dynamic `import()` the first time they are selected; until loaded the previous dictionary keeps rendering (no raw keys), failures keep the previous locale with a translated notice. Key parity across locales stays enforced by a test. `npm run build` must report no budget warning.
- **D12 Concurrency.** `tournament_draws.revision integer not null default 0`, incremented by every draw write (save draft, publish/unpublish, delete, result upsert). Writes go through SQL functions (new additive migration) that take the expected revision and fail with a distinct error when it changed, inside one transaction (result upsert = revision check + upsert + revision bump). The API reads the snapshot (with revision), validates with the domain, then calls the function; a revision conflict maps to 409 `draws.concurrent_modification` (translated in the frontend, which reloads the draw). Removes the residual races documented in L8/L10.
- **D13 Courts.** Result body accepts `courtId` (optional); the API validates the court belongs to the tournament's complex (or the tournament's `selected_court_ids` when set) and the organization, stores `court_id` and the court's current name in `court_name`; free-text `courtName` without id remains allowed. Public responses keep only `courtName`. The dialog lists the tournament's courts (existing courts API) and keeps a free-text "other court" option.
